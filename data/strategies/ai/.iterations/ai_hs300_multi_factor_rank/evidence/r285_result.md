# R285 宏观门禁数据时间戳归档可行性审计（2026-10-28）

## 范围

本轮按预注册只读检查 R275 期限利差候选所依赖的宏观数据缓存、扩展时序表存储方式、拉取和因子装配调用链。没有调用外部 provider、运行回测或修改生产代码。R285 已登记到本机 3018 面板，POST 与读回均 HTTP 200；候选 ID `7890111615854e2083f80d6f3d557649`，状态 `pending`。

## 发现

- 三类宏观本地原始缓存只包含观测日期、曲线/指数和数值列，没有发布时间、供应商采集时间或版本字段。已有 R279 AkShare 只读探测也显示债券收益率、信用曲线和沪深300 PE 响应都没有时间溯源列；本轮没有重复调用 provider。
- `alt_hs300` 是 `timeseries` 配置，但没有拉取配置。其分区键为 `date=YYYY-MM-DD`；写入时会把同一分区内同一 symbol 的重复行合并并保留最后一行，故后续重拉会替换旧观测，不能保留同日多次响应或修订 vintage。
- 当前拉取代码在解析时只返回 JSON 行，不保存 HTTP 响应头或原始响应体。`last_run` 只保留配置中的最近一次运行时间，不与各行绑定，也不是供应商发布时间。
- 扩展因子读取按 `(symbol, date)` 唯一值装配，因此当前数据链适合按日期使用单一观测值，不具有按当时可知版本重建历史的能力。
- R276 已记录的 2,132 个另类数据分区哈希本轮复核无不匹配；R276、R278、R279 源证据哈希与冻结值一致。

## 结论与下一步

只启用现有定时拉取不能建立满足审计要求的前瞻 PIT 数据：本地收件时间、来源发布时间、原始响应/哈希和同日修订记录没有按每次观测追加保存。系统外单独维护不可变的逐次采集证据日志在概念上可以记录本地接收时间与 payload 哈希，但无法凭空补出供应商发布时间；后者仍需供应商明确提供或保留可验证的原始响应元数据。当前 R275 宏观候选因此还不具备可证明 PIT 的数据条件。

本轮没有回测、provider 拉取、行情或缓存写入、轮询变更、paper 账户/订单或策略源码改动。R275 保持 `research_only`，生产保持 `pause_production`，没有理由放宽门槛。若要真正开展前瞻观察，下一步应先提出并评审一个范围独立、追加写入、以抓取批次为版本、记录 UTC 接收时间/来源/观测日期/响应哈希且不覆盖旧记录的研究采集方案；在有批准的实现和明确来源时间契约前，不宣称已经开始有效观察期。
